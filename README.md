# 元素極限：火柴人大亂鬥

### ▶ [點這裡直接在瀏覽器玩](https://supercoder592.github.io/stickman-game/)

> 首次載入約 46 MB（wasm + 資源），請耐心等進度條跑完。
> 網頁版為 WebGL（Compatibility）建置，**不支援連線對戰**（瀏覽器不能用 ENet／UDP），
> 連線功能請下載原始碼用 Godot 執行。

Godot 4 橫向動作遊戲原型。角色、關卡、UI、以及 9 種元素招式的全部特效
**完全由 GDScript 程式繪製**（`_draw()` + `CPUParticles2D` + `Line2D`），
專案內沒有任何 png / 圖片素材，`icon.svg` 只是專案圖示。

美術方向取材自《鬼滅之刃》的呼吸法筆觸（濃墨描邊的毛筆新月斬、浮世繪浪頭、漫畫集中線）
與寶可夢的招式能量演出（法陣、向心吸能、光束），細節見 `docs/element-design.md`。

## 網頁版建置

```bash
# 需要先在 Godot 編輯器安裝匯出範本（Editor → Manage Export Templates）
godot --headless --path . --export-release "Web" ../build/web/index.html
```

`export_presets.cfg` 已關閉執行緒支援，因為 GitHub Pages 不會送 COOP/COEP 標頭，
開啟執行緒會導致 SharedArrayBuffer 不可用而無法啟動。

網頁版有三個環境限制，程式中已各自處理：

| 限制 | 處理方式 |
| --- | --- |
| 瀏覽器讀不到系統字型 | 內建 Noto Sans TC（`assets/fonts/`），否則中文全變空白方塊 |
| 只支援 WebGL，不能用 Forward+ | `rendering_method.web` 覆寫為 `gl_compatibility`（泛光仍可用） |
| 不支援 ENet／UDP | 網頁版隱藏「連線對戰」，選單改以名稱分派避免索引位移 |

## 執行方式

1. 用 Godot 4.3 以上開啟本資料夾（`project.godot`）。
2. 按 F5 執行，主場景為 `scenes/main.tscn`。
3. 第一次執行會跳出商店，請先從四大基礎元素中免費挑一個。

## 連線對戰（區域網路，4 位數房號）

主畫面 →「連線對戰」→ 建立房間（顯示 4 位數房號）或 加入房間（輸入房號）
→ 雙方各自選元素並按 Enter 準備 → 主機自動開打。

**房號怎麼運作**：不需要任何外部伺服器。主機在 UDP 24566 監聽；
加入方把房號廣播到 `255.255.255.255:24566`，房號相符的主機回覆，
加入方從封包來源取得 IP，再用 ENet 連 24565。
因此雙方必須在**同一個區域網路**（同一個 Wi-Fi，或其中一台開手機熱點）。

**同步模型**：主機權威。主機跑完整模擬（雙方角色、招式、傷害），
客戶端只送輸入、套用狀態快照（30Hz），本地仍播放招式特效但角色為 `net_puppet`，
血量與位置一律以主機為準，因此不會雙重扣血或分歧。

## 跨網連線（P2P 打洞，失敗自動轉中繼）

家用路由器的 NAT 不會把外部連線轉進內網，所以兩台不同網路的機器無法直接互連。
**「P2P 就不用伺服器」是常見的誤解** —— NAT 打洞本身就需要一個雙方都連得到的
第三方來牽線（WebRTC 的 signaling server 也是同一回事）。

本專案的解法是**中繼伺服器**：只要有一台雙方都連得到的機器跑它，
玩家兩邊都不用碰路由器。

### 啟動中繼伺服器

```bash
godot --headless --path . -- --relay        # 監聽連接埠 24570
```

把它跑在有公開 IP 的機器上（VPS、或自己 PC 但把 24570 轉發出去）。
一台中繼可同時服務多個房間。

### 玩家端

主畫面 →「連線對戰」→「跨網連線（中繼伺服器）」→ 輸入中繼位址（會記住）
→ 輸入 4 位數房號。**雙方輸入同一台中繼、同一組房號即可配對**，
先連進來的自動成為主機。

實作上遊戲協定完全沒變：所有訊息包進 `_rpc_relay_msg`，中繼只負責
把同房間 A 送來的封包原樣轉給 B，主機權威模型照舊。

### P2P 是怎麼運作的

連線時**先嘗試 UDP 打洞**：

1. 兩邊各綁一個本地 UDP 連接埠 `L`，用它向牽線伺服器登記房號
   —— 伺服器看到的來源位址就是自己在 NAT 上的**外部映射**
2. 伺服器把雙方的外部位址互相告知
3. 兩邊用**同一個** socket 互相狂送封包，各自的 NAT 因而打開回程通道
4. 關閉 UDP，改讓 ENet 綁**同一個本地連接埠 `L`**，沿用剛打通的映射

成功之後**流量完全不經過伺服器**，延遲最低、伺服器負擔幾乎為零。
牽線伺服器只在最初幾秒用到。

打不通時（symmetric NAT、電信商 CGNAT）會在 7 秒後**自動退回中繼**，
玩家不需要做任何事。這也是商業遊戲的標準做法。

| 方案 | 需要什麼 | 狀態 |
| --- | --- | --- |
| 區網房號 | 同一個 Wi-Fi／熱點 | ✅ 已實作並測試 |
| IP 直連 | 對方做連接埠轉發 24565 | ✅ 已實作（未實機測跨網） |
| **P2P 打洞** | 一台牽線伺服器跑 `--relay` | ✅ 已實作，本機測過協定流程 |
| 中繼轉送 | 同上（P2P 失敗時自動使用） | ✅ 已實作，本機三行程測過 |
| WebRTC | 需 signaling server + 原生擴充 | ❌ 未做（打洞已能達到同樣效果） |

> ⚠️ **打洞的真實 NAT 穿透無法在單機驗證** —— 本機兩個行程之間沒有 NAT，
> 測試只證明了牽線、位址交換、socket 交接、ENet 直連這條協定鏈正確。
> 實際成功率要在兩個不同網路的裝置上才測得出來。

## 手機模式

`F5` 切換（觸控裝置會自動開啟）。開啟後對戰畫面會出現左側虛擬搖桿與右側按鈕
（跳、普攻、三個招式鍵，招式鍵外緣有冷卻進度弧）。
桌機上也接受滑鼠操作，方便不用真手機就能測。

## 遊戲流程

**主畫面 → 單機／連線對戰 → 選元素 → 1v1 對戰 → 結算 → 回主畫面**

對戰是一對一單挑：雙方各 200 血，打完一方即結束。
元素在開戰前決定 —— 先選自己的，再選對手的（可指定，也可選「隨機」）。
勝利 +320 金幣、敗北 +90 金幣，金幣用來在選元素畫面解鎖冰霜（750）、劇毒（1000）、
熔岩（1200）、鋼鐵（1500）、龍之力（3000）。進度存於 `user://stickman_save.json`。

## 元素與招式

9 個元素，每個元素三招，共 27 招。招式一是各元素的本命招（獨立檔案、特效最完整），
招式二、三由 `scripts/skills/move_kit.gd` 的七種元件（彈道／場域／天降／地刺／吐息／突進／壁障）
組合而成，再以顏色、形狀與數值做出辨識度。

**冷卻規則**：招式一與招式二**沒有冷卻**（HUD 上標 `∞`），只保留 0.26 秒的施放後搖，
避免連打時動作與特效互相蓋掉。招式三清一色是防禦／增益／大範圍招
（護盾、凪、鋼鐵頭殼、毒霧結界、流星群…），維持冷卻。
這條規則寫在 `Fighter.FREE_MOVE_COUNT`，改一個常數就能調整幾招免冷卻。

## 驗證

已在 **Godot 4.7.stable** 實測通過：

```bash
# 煙霧測試（無視窗，跑完 9 種招式，任何錯誤都會印到 stderr）
Godot_console.exe --headless --path . --fixed-fps 60 --quit-after 2400 res://dev/smoke.tscn

# 產生招式與介面截圖到 dev/shots/
Godot_console.exe --path . --resolution 1280x720 res://dev/shot.tscn

# 連線測試（區網直連）：開兩個行程
Godot_console.exe --headless --path . res://dev/net_test.tscn -- --role=host
Godot_console.exe --headless --path . res://dev/net_test.tscn -- --role=client

# 連線測試（跨網中繼）：開三個行程
Godot_console.exe --headless --path . -- --relay
Godot_console.exe --headless --path . res://dev/net_test.tscn -- --role=relay_a
Godot_console.exe --headless --path . res://dev/net_test.tscn -- --role=relay_b
```

煙霧測試目前輸出 0 個錯誤。注意 `--headless --import` 只會註冊全域類別、**不做深度型別檢查**，
招式腳本是延遲載入的，所以解析錯誤只有實際裝備該招式時才會浮現 —— 驗證請跑 `smoke.tscn`，
不要只看 `--import` 有沒有過。

## 加入新元素

1. 在 `scripts/skills/` 新增一支 `extends Skill` 的腳本，覆寫 `_on_setup()`
   （設定 `id`、`cd_max`）、`_use()`、必要時再覆寫 `_tick()` 與 `can_use()`。
2. 特效寫成該檔案內的 `class XXX extends Node2D` 內部類別，
   丟進 `arena.fx_back` 或 `arena.fx_front`。
3. 在 `game_state.gd` 的 `ELEMENTS` 加一筆資料，並把 id 加入 `ELEMENT_ORDER`。

商店、HUD、切換鍵全部由這張表驅動，不需要改動其他地方。
