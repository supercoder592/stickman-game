# 十位角色設計

> 資料表：`scripts/characters.gd`　被動實作：`scripts/fighter.gd`　選角畫面：`scripts/ui/character_select.gd`

## 為什麼要有「角色」這一層

原本的遊戲只有「元素」—— 換元素等於換三招，但兩個玩家的血量、移速、跳躍、
普攻手感完全一樣，體型也只差在玩家自己買的造型。這樣一來「選誰」只是選招式。

角色這一層把三件事綁在一起：

| 面向 | 誰決定 | 目的 |
| --- | --- | --- |
| 三招 | 角色的**元素**（十個元素一一對應） | 玩法差異 |
| 數值與被動 | 角色本身 | 手感差異：誰快、誰硬、誰高風險 |
| 剪影（部位 + 體型） | 角色的預設穿著 | 遠看就認得出是誰 |

平衡基準：血量 200、移速 300、跳躍 720、攻防倍率 1.0、普攻間隔倍率 1.0。
十位角色都在這個基準 ±25% 以內，沒有純粹的上位相容。

## 被動是怎麼實作的

被動分兩種：

1. **純數值**（鋼體、龍威）—— `apply_character()` 設好 `atk_mul` / `def_mul` 就結束了，
   `passive_id` 留空。
2. **有邏輯**（燃血、潮息、輕身、凍甲、毒素共鳴、熔岩之軀、疾電連打、殘影）——
   `passive_id` 對應到 `fighter.gd` 的兩個地方：
   - `outgoing_multiplier()`：自己打出去的傷害要不要加成（燃血、毒素共鳴）
   - `_passive_on_hit()`：被打中之後的反制（凍甲、熔岩之軀、殘影加速）

### 傷害倍率怎麼找到「攻擊者」

30 招的傷害都是各自呼叫 `Fighter.take_damage()`，沒有傳攻擊者。
與其改動每一個呼叫點，`take_damage()` 反過來查：本作固定 1v1，
**傷害必定來自另一隊那一位**，所以 `attacker()` 直接取對手即可（`fighter.gd`）。

### 連線時誰說了算

主機權威的模型沒有變。需要擲骰或改狀態的被動（殘影的閃避、潮息的回血、
凍甲與熔岩之軀的反制）都只在權威端執行 —— 客戶端的角色是 `net_puppet`，
`take_damage()` 會在扣血前就返回，血量一律以主機快照為準，兩邊不會分歧。

## 剪影：遠看要認得出是誰

角色的預設穿著直接寫在 `Characters.LIST[id].look`，用的是既有的五個部位
（頭／胸／腹／腳／手）加上體型倍率 `build` / `limb_w` / `head_r`：

- 鋼牙：面甲 + 胸甲 + 裙甲 + 護脛，`build 1.16`、`limb_w 1.30` —— 全場最壯
- 疾羽：兜帽 + 雙翼，`build 0.94`、`limb_w 0.86` —— 全場最瘦、帶殘影
- 灼岳：巨角 + 胸甲 + 重靴，`build 1.12` + 發光
- 夜刃：般若面具 + 大披風 + 尖刺拳套，帶殘影

商店買到的部位會**蓋掉**角色的預設部位（`Game.character_look()`）：
沒換過的部位維持角色原樣，換過的就照玩家的意思。
連線對手與 AI 對手一律用角色預設穿著 —— 那是對方的裝扮，本機沒有資料。

## 加入第十一位角色

1. 在 `scripts/characters.gd` 的 `LIST` 加一筆，並把 id 放進 `ORDER`。
2. 如果要用新元素：照 `README.md`「加入新元素」的步驟寫三招，
   再把元素 id 填進角色的 `element`。沿用既有元素也可以（變成同招不同手感的角色）。
3. 需要新被動時：在 `Characters` 寫好 `passive_id` 與說明文字，
   再到 `fighter.gd` 的 `apply_character()` / `outgoing_multiplier()` / `_passive_on_hit()`
   加上對應分支。

選角畫面、商店、大廳、HUD 全部由 `Characters.ORDER` 驅動，不需要再改其他地方。
