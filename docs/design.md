# STEEL CLASH 設計與架構

這份文件說明「為什麼是這樣寫的」。每一節都對應到 `src/` 底下的一支檔案。

---

## 1. 美術：街機格鬥的賽璐璐上色（無任何圖檔）

整個遊戲沒有一張圖、沒有一個音檔，畫面全部是 Canvas 2D 即時畫出來的。
目標是**90 年代 2D 街機格鬥的畫法**：鮮豔實色、硬邊的明暗分界、粗黑描邊、
看得見肌肉與表情。不是漸層寫實，也不是霓虹線框。

`material.js` 是這一層的核心，一塊形狀會經過五道：

1. **形狀**：多邊形、膠囊，或 `smooth()` 把折線磨圓的有機輪廓（身體、頭顱、靴子）。
2. **三階實色**：沿著光源向量 `LIGHT` 分成亮面／本色／陰影三塊。
   關鍵是**硬邊** —— 在漸層的同一個位置放兩個色停，就會出現一刀切的分界，
   這正是街機 sprite 的上色法（`shade()` 的 `cel` 模式）。
3. **反光**：金屬在亮面邊緣多一條白。
4. **遮蔽陰影**：零件交界處壓深一點（`ao`）。
5. **粗黑描邊**：每塊形狀都描一圈 2.4px 的近黑色，合起來就是 sprite 的硬輪廓。

材質表 `MAT` 有 steel / iron / darkIron / brass / rust / leather / cloth / skin /
rubber / bone。`tint()` 會把角色的主題色吃進 `base`，再由 `base` 推出亮面（加白）
與陰影（壓暗偏冷），所以染完是一整組協調的三階色，而不是一塊灰。
**衣服直接用角色的主題色** —— 街機格鬥就是靠一件鮮豔的衣服認人。

角色的辨識度還靠三件事：**武術裝扮**、**裸露的手臂**（上臂有二頭肌的鼓起）、
**肌肉溝線**（`creaseLine()` 在上好色的形狀裡加胸肌、腹肌、衣褶的線），
以及**臉**。臉是分兩層畫的：頭骨的輪廓本身就走完一條側臉的稜線
（額頭 → 眉弓 → 眼窩凹 → 鼻樑 → 鼻尖 → 人中 → 唇 → 下巴 → 下顎角 → 後腦），
`drawFace()` 再往上疊五官 —— 顴骨與下顎的陰影塊、凹進去的眼窩、眼白、
虹膜與瞳孔、一條粗黑的上眼瞼（眼睛的重量全在這裡）、楔形的眉毛、
鼻樑暗面與鼻孔、上唇實線與下唇陰影、有內耳線的耳朵。
`drawHair()` 用剪影做短髮／爆炸頭／馬尾／光頭，另有會飄的綁頭帶。

### 動作（`rig.js`）

每個動作都是一組四肢角度，攻擊類再吃一個 `k`（0→1 的進度）。
要打起來有手感，靠的是三件事：

1. **出招的節奏不是線性的**。`swingK(a, b)` 把一招切成三段，各用不同曲線：
   蓄力用 `p²`（越後面越快）、打出用 `1-(1-p)³`（一瞬間到位）、
   收招用比較平的曲線（慢慢沉回來）。打出去那一格才會「快」。
2. **預備動作（anticipation）**：重擊會先往後拉到 −1.25 弧度再劈下去，
   昇龍會先蹲 12 再拔起來 —— 觀眾先看到「要出招了」，打中才有份量。
3. **動作之間會內插**（`blendRig()`）。直接換一副骨架，畫面上會「啪」地跳一下；
   每一幀往目標靠近 42%，轉場就順了。**受擊與倒地例外，直接切** ——
   那兩個要的就是衝擊感。

另外像跑步時手肘會跟著收放、迴旋踢時上身往後倒配重、被打中時頭先甩出去
身體才跟上，都是同一個目的：讓每個動作看起來有重心。

人體也不是一段一段接起來的：`limbPath()` 把「肩→肘→腕」「髖→膝→踝」畫成
**一條**有粗細變化的連續形狀，關節處不會出現一顆球的輪廓（那是玩具人偶的特徵）。

場地是亮的：藍天 + 被天光洗淡的城市 + 木地板，沒有暗角、沒有顆粒、沒有雨。
街機格鬥的畫面要乾淨，打架的人必須是全畫面最搶眼的東西。

| 元件 | 位置 | 用途 |
| --- | --- | --- |
| `shade` | `material.js` | 三階實色 + 反光 + 遮蔽 + 粗黑描邊，所有實體共用 |
| `creaseLine` | `material.js` | 在形狀裡加肌肉溝、衣褶、甲片分線 |
| `limbPath` | `material.js` | 一整條四肢，沒有關節球 |
| `smooth` | `material.js` | 把折線磨圓的有機輪廓 |
| `groundShadow` | `material.js` | 接地陰影：跳越高、越淡越散 |

| `panel` / `stencil` | `gfx.js` | UI 的舊鋼板與模板字 |
| `neonStroke` / `glowFill` | `gfx.js` | **只剩招式特效在用**（火、電、能量本來就會發光） |

場景（`render.js`）預先畫好一張靜態背景（天空漸層 → 雲 → 三層城市剪影，每棟樓
自己有明暗與受光邊 → 大氣透視的霧 → 吊車、煙囪 → 矮鐵網）。
背景**畫在世界座標裡**、只做水平視差，所以地平線永遠貼齊地面，鏡頭拉遠拉近都不會
出現接縫。鏡頭本身是格鬥遊戲的老規矩：兩人越近拉得越進（zoom 1.36～2.05）。

## 2. 角色：武器定義一切

`rig.js` 只回答「骨頭在哪裡」：以腳底為原點算出髖、胸、頸、頭與四肢的關節座標，
每個動作（idle / run / jump / 三段連段 / 重擊 / 蓄力 / 昇龍 / 俯衝 / 受擊 / 倒地…）
都是一組四肢角度。攻擊類動作吃一個 `k`（0→1 的進度），所以同一支函式就能做出
「蓄力 → 打出 → 收手」的節奏。比例照真人抓：腿約佔身高一半、頭約身高的 1/6。

`render.js` 負責「骨頭長什麼樣」：倒三角的軀幹、包住肩頭的甲片、護膝、靴子，
再依角色的 `gear` 掛上頭部（焊工面罩／防毒面具／兜帽／鋼盔／護目鏡／角盔／戰術面罩）、
背部（工具腰帶／盤起來的鎖鏈／破布斗篷／刀鞘）與肩甲。

**辨識度來自武器**。`drawWeapon()` 為十把武器各寫一套造型，
並吃 `weapon.hold`（相對前臂的握持角度）與 `twoHand`（後手也扶在柄上）：

| 角色 | 武器 | 畫法重點 |
| --- | --- | --- |
| 鐵砧 ANVIL | 破壞錘 | 長柄 + 方形錘頭，撞擊面有磨亮的痕跡 |
| 鉤索 HOOK | 鉤爪 | 護臂發射器 + 三爪 + 垂下來的鎖鏈 |
| 裂齒 RIPPER | 鏈鋸 | 機身 + 導板，鋸齒會跟著時間跑 |
| 鉤魂 REAPER | 鎖鏈鐮 | 手上握鏈，鐮刀甩在體外，出招時鏈長會變 |
| 疾影 WRAITH | 雙匕 | 前後手各一把，背後兩個刀鞘 |
| 斷頭 CLEAVER | 戰斧 | 厚柄 + 單邊大斧刃 |
| 連棍 FLAIL | 三節棍 | 三段包鐵木棍用短鏈串起來，後兩節會跟著甩 |
| 長戟 LANCER | 長柄戟 | 全場最長的柄 + 矛尖 + 側斧 |
| 鐵拳 BRAWLER | 鐵指虎 | 纏布的拳頭 + 四顆指節鐵疙瘩 + 護手背板 |
| 撬棍 PRYBAR | 鐵撬 | 彎折的扁鋼，一端鴨嘴、一端尖爪 |

體型（`build.scale` / `bulk`）再把差距拉開：鐵砧壯一圈、疾影瘦一圈 ——
遠遠一眼就知道對面是誰。

### 武術裝扮（`gear.outfit`）

十個人都是武術家的打扮，四種底：`gi` 開襟道服／`vest` 無袖背心／
`sash` 打赤膊只繫腰帶／`robe` 長袍。每一套都由同樣幾個零件組出來：

* **上衣**：從肩線罩到腰，前襟往內收；`gi` 與 `robe` 再疊一片交叉的前襟，
  兩片合起來就是 V 領 —— 道服的招牌。
* **衣襬**：前後各一片垂下來、中間開衩，腿才踢得出去（一整片裙子會擋住動作）。
* **腰帶**：寬布帶 + 結 + 兩條會擺動的帶尾，用角色的第二色。
  它**畫在腿之後**，否則會被褲子蓋掉。
* **道服褲**：寬鬆、外側比內側寬（布會被甩出去），褲口束在小腿肚，
  露出的小腿再纏一圈綁布，最後是布鞋。
* **拳帶**：白布從手肘下方纏到手腕，上面有三道斜的纏繞縫。
* 肩膀可以是 `sleeve`（道服短袖）、`plate`／`heavy`（護肩）或 `none`。

### 武器的細節

每把武器都不只是剪影，而是由「材料會怎麼組裝」推出來的：
纏繩的握把（`gripWrap()`，一圈一圈的斜紋）、把金屬件固定在木柄上的
黃銅鉚釘（`rivets()`）、開過鋒的刃面亮線（`bevel()`）、血槽、箍、護條、
撞擊面的磨亮痕跡與缺角。鏈鋸有引擎機殼、拉繩、排氣口與火星塞；
三節棍每一節兩端都有銅箍、節與節之間是真的鏈；長戟的側斧開了月牙口、背面有鉤。

## 3. 戰鬥

### 招式表（`combat.js`）

普攻是時間制的三段式資料：`{ dur, hit:[起,訖], dmg, hitstun, kb, reach }`。
判定框 `reach` 是相對角色的矩形，會乘上武器的距離倍率（長戟最遠、拳套最短），
所以「看起來打得到」和「判定打得到」是一致的。

### 兩個結算入口（`fighter.js`）

所有傷害都只走兩支函式：

* `dealDamage(target, hit)` —— 我方打出去。攻擊倍率、以及「對殘血 +30%」「對硬直中 +25%」
  「離得越遠／越近越痛」這類**加成型被動**在這裡。
* `receiveHit(from, hit)` —— 對方打進來。閃避、格擋、減傷、擊退、硬直、狀態異常，
  以及反制型被動的掛點都在這裡。

新增招式不需要重寫任何結算邏輯，因為招式只是組出一個 `hit` 物件丟進去。

### 狀態異常全部是物理性的

**這個遊戲沒有元素、沒有五行、沒有魔法。** 十個人都只是拿著鐵器互毆，
所以狀態異常只有三種，而且都能用物理解釋：

| 狀態 | 來源 | 效果 |
| --- | --- | --- |
| 流血 `bleed` | 鏈鋸、雙匕、鐵蒺藜 | 持續掉血，最多疊 8 層，4 秒 |
| 暈眩 `stagger` | 撬棍的打樁、鉤索擒拿、突進類重擊 | 站著不能動也不能出招 |
| 腿傷 `slow` | 鐵蒺藜 | 移速下降 |

另外還有兩個不算狀態的標記：`marked`（被鉤索鉤中，對方接下來打你更痛）
與 `armor`（霸體，出招途中不被打斷）。

### 格擋不佔按鍵

朝遠離對手的方向推就是格擋（街機的老規矩），傷害降到 28%、不吃硬直、還會回氣。
這樣按鍵只要七顆（跳／輕／重／技能 ×2／必殺／閃避），手機也排得下。

### 手機（`touch.js` / `index.html`）

畫布是固定的 1280×720 邏輯解析度，用 CSS 等比縮到螢幕上。
一支 844×390 的手機縮完是 693 CSS px 寬，也就是 **1 邏輯單位 ≈ 0.54 CSS px** ——
所以觸控鍵的半徑要 56 以上，摸起來才有 60 CSS px，達到可以安心按的大小。
按鈕的尺寸不是用「看起來剛好」決定的，是從這個換算回推的。

其他幾個手機上才有的決定：

* **搖桿沒有固定位置**：左半邊按下去的那一點就是圓心，手指不必先找圈圈。
* **技能冷卻畫在按鈕上**（由下往上補滿的暗色 + 剩餘秒數），
  所以底部那排技能格在觸控裝置上就不畫了，省下一整條空間。
* **左上角一顆 `‖`** 代替 Esc，塞在血條與計時器中間的空隙。
* **直向時不玩**：用一個純 CSS 的 `@media (orientation: portrait) and (pointer: coarse)`
  蓋一層「請把手機轉成橫向」，不進遊戲迴圈，也就不會有人在一條 390×219 的
  窄帶裡打架。
* 選單的操作提示會依 `isTouch()` 換成點擊版本，不會叫手機玩家按 Enter。

### 打擊感

命中時同時發生：頓幀（`fx.stop`，重擊 90ms）、震屏、白閃、火花、放射線、
傷害數字、刀光，音效同步。**頓幀是打擊感的一半** —— 世界暫停幾格，特效照跑。

## 4. 招式元件庫（`skills.js`）

十位角色的 20 個技能 + 10 招必殺如果各寫各的，品質會參差不齊，所以拆成可組合的元件。
每個元件都吃參數，角色資料只填 `kind` 與數值：

| 元件 | 誰在用 |
| --- | --- |
| `slam` 砸地衝擊波 | 鐵砧 |
| `charge` 蓄力重擊 | 鐵砧、斷頭 |
| `quake` 全場地震 | 鐵砧必殺 |
| `grapple` 鉤索擒拿（把人拉過來） | 鉤索 |
| `zipline` 飛索突進（把自己拉過去） | 鉤索 |
| `flurry` 連打 | 鉤索必殺、疾影必殺、鐵拳必殺、連棍必殺 |
| `sustained` 持續傷害（鋸／噴射） | 裂齒、裂齒必殺 |
| `dashStrike` 突進 | 裂齒、長戟、鐵拳、撬棍 |
| `chainSwing` 鎖鏈迴旋 | 鉤魂 |
| `boomerang` 拋出去再收回 | 鉤魂 |
| `reap` 瞬移到背後斬 | 鉤魂必殺 |
| `blink` 瞬移斬 | 疾影 |
| `rushCombo` 連斬 | 疾影、撬棍必殺 |
| `uppercut` 上挑 | 斷頭 |
| `cleave` 裂地斬 | 斷頭必殺 |
| `ward` 架勢（減傷＋霸體＋推開） | 連棍 |
| `sweep` 橫掃 | 長戟、連棍 |
| `lanceRush` 一閃突刺 | 長戟必殺 |
| `burst` 周身爆發 | 鐵拳 |
| `zone` 場域（鐵蒺藜） | 撬棍 |

元件分兩類：有自己生命週期的 **Entity**（飛行物、場域、光束、地刺、衝擊波），
以及「一段時間內操控施放者」的 **Routine**（突進、連斬、瞬移、蓄力）。
角色資料只填 `kind` 與參數，視覺再用自己的顏色與形狀做出辨識度。

## 5. 輸入：一種格式打天下（`input.js`）

鍵盤、觸控、AI、網路對手，最後都收斂成同一個 `InputFrame`：

```js
{ x: -1|0|1, up, down, edges }   // edges 是按鍵「剛按下」的位元遮罩
```

因為只有一種格式，`Fighter` 完全不知道操作者是誰 ——
單機、雙人同機、連線走的是同一條程式路徑，不必維護三套。

`edges` 用位元遮罩是為了連線：一幀的輸入就是四個數字。

## 6. AI（`ai.js`）

AI 不碰戰鬥邏輯，只產生 `InputFrame`，所以它一樣吃冷卻、硬直與格擋規則，不會作弊。
難度只調整兩個數字：反應間隔與積極度。行為是距離導向的 ——
近距離挑普攻或後退、中距離挑合適的技能、對手在出招時會往後格擋、氣滿了會找機會放必殺。
虛影類招式對 AI 是真的有效：`battle.apparentTarget()` 會把虛影當成目標回傳。

## 7. 連線（`net.js` / `server/relay.js` / `battle.js`）

* **中繼伺服器**只做一件事：同房號的兩個人互轉封包。它不懂遊戲規則，
  所以遊戲改版完全不用動伺服器。手寫 WebSocket（RFC 6455 必要子集），零相依套件，
  同一支程式順便把遊戲的靜態檔案服務出去。
* **主機權威**：先進房的人是主機，跑完整模擬，每秒 20 次送快照；
  客戶端只送輸入（60Hz、每幀四個數字）與照著快照畫。
* **客戶端不算傷害**：`Battle.authoritative = false` 時 `dealDamage()` 直接回傳 false，
  所以即使客戶端在本地重播招式特效，也不會扣到血。
* **招式重播**：主機把「誰放了什麼招」轉過去，客戶端跑同一支 `runSkill`，
  於是彈道、光束、地刺這些東西兩邊都看得到。
* **索引對齊**：快照裡 0 號永遠是主機、1 號永遠是客戶端，客戶端照樣把自己畫在自己那側。
  （前一版 Godot 專案就是在這裡出過 bug：客戶端的血條顯示的是對手的血量。）
* **心跳**：伺服器每 15 秒 ping，45 秒沒回應就踢掉，
  否則瀏覽器分頁被強制關掉時那個房號會永遠卡在「已經有兩個人」。

## 8. 音效（`audio.js`）

全部即時合成，沒有音檔：打擊是帶通噪音 + 方波、重擊多一層低頻鋸齒、
揮空是掃頻噪音、必殺是三個疊起來的鋸齒和弦。
背景音樂是 16 步的循環（低音線 + 琶音），音量壓得很低當底噪。
瀏覽器規定要有使用者互動才能出聲，所以 AudioContext 延到第一次按鍵／點擊才建立。

## 10. 打包（`tools/build.js`）

瀏覽器用 `file://` 開啟時會擋下 ES module，所以「點兩下就能玩」的版本要把所有模組
塞進同一個 HTML。做法是把每支模組的原始碼存成字串，在瀏覽器裡轉成 `blob:` URL 再互相
import —— **程式碼一個字都不用改**，也就不會有「打包版和開發版行為不同」的問題。
打包器會做相依排序，發現循環 import 會直接報錯（目前的相依圖是無環的）。
