# NEON CLASH 設計與架構

這份文件說明「為什麼是這樣寫的」。每一節都對應到 `src/` 底下的一支檔案。

---

## 1. 美術：霓虹幾何（NEON FACET）

整個遊戲沒有任何圖檔，所有東西都是 Canvas 2D 畫出來的。
視覺語言只有一條規則：**深色實心 + 霓虹描邊 + 加法光暈**。

光暈不用 `ctx.shadowBlur`（在低階裝置上非常慢），改成「同一條路徑描三次」：
最外圈粗而淡、中圈中等、最內圈是亮芯（`gfx.js::neonStroke`）。
這樣一根手臂、一把劍、一道斬擊用的都是同一個函式，風格自然統一，
而且三次描邊的成本遠低於一次高斯模糊。

| 元件 | 位置 | 用途 |
| --- | --- | --- |
| `neonStroke` / `neonPlate` | `gfx.js` | 角色的每一塊板子、UI 外框 |
| `glowFill` | `gfx.js` | 特效的發光填色（走 `lighter` 混色） |
| `crescentPath` | `gfx.js` | 新月斬：所有武器的刀光 |
| `taperPath` | `gfx.js` | 錐形肢體，是骨架的基本形狀 |
| `ngonPath` | `gfx.js` | 六角形 —— 這套美術的招牌形狀（頭、粒子、計時器） |

場景（`render.js`）是霓虹夜城：漸層夜空 → 帶橫向切線的落日 → 兩層城市剪影（窗光會閃）
→ 透視地板網格 → 場地兩側的能量牆。天空畫在畫面座標並帶視差，地板畫在世界座標，
所以鏡頭縮放時遠景幾乎不動、地面會跟著推近，空間感比整張一起縮放好很多。

## 2. 角色：骨架 + 零件

`rig.js` 只回答「骨頭在哪裡」：以腳底為原點算出髖、胸、頸、頭與四肢的關節座標，
每個動作（idle / run / jump / 三段連段 / 重擊 / 施法 / 昇龍 / 俯衝 / 受擊 / 倒地…）
都是一組四肢角度。攻擊類動作吃一個 `k`（0→1 的進度），所以同一支函式就能做出
「蓄力 → 打出 → 收手」的節奏。

`render.js` 負責「骨頭長什麼樣」：每根骨頭畫成錐形板子，再依角色的 `look` 掛上
頭部樣式（面罩／王冠／般若／天線／稜鏡／兜帽／犄角／頭盔／光環／鬼面）、
背部零件（線圈／披風／旗／雙翼／浮游機／尾巴／核心／噴射背包／雙刀）、
肩甲（輕／板／厚重）與武器（拳套／劍／雙刀／長槍／爪／法杖／球杖／重錘／盾）。

**剪影就是辨識度**：十位角色的差異不是換色，而是體型比例（`build`）加上這些零件。
鋼獄壯一圈、疾翎瘦一圈又有翼、熔岳扛著一把比人還大的錘子 —— 遠遠一眼就知道是誰。

## 3. 戰鬥

### 招式表（`combat.js`）

普攻是時間制的三段式資料：`{ dur, hit:[起,訖], dmg, hitstun, kb, reach }`。
判定框 `reach` 是相對角色的矩形，會乘上武器的距離倍率（長槍 1.38、拳套 0.88），
所以「看起來打得到」和「判定打得到」是一致的。

### 兩個結算入口（`fighter.js`）

所有傷害都只走兩支函式：

* `dealDamage(target, hit)` —— 我方打出去。攻擊倍率、以及「燃燒 +15%」「中毒 +25%」
  「距離越遠越痛」這類**加成型被動**在這裡。
* `receiveHit(from, hit)` —— 對方打進來。閃避、格擋、減傷、擊退、硬直、狀態異常、
  以及「凍甲反制」「熔岩反燒」這類**反制型被動**在這裡。

新增招式不需要重寫任何結算邏輯，因為招式只是組出一個 `hit` 物件丟進去。

### 格擋不佔按鍵

朝遠離對手的方向推就是格擋（街機的老規矩），傷害降到 28%、不吃硬直、還會回氣。
這樣按鍵只要七顆（跳／輕／重／技能 ×2／必殺／閃避），手機也排得下。

### 打擊感

命中時同時發生：頓幀（`fx.stop`，重擊 90ms）、震屏、白閃、火花、放射線、
傷害數字、刀光，音效同步。**頓幀是打擊感的一半** —— 世界暫停幾格，特效照跑。

## 4. 招式元件庫（`skills.js`）

20 位角色技能 + 10 招必殺如果各寫各的，品質會參差不齊，所以拆成可組合的元件：

| 元件 | 誰在用 |
| --- | --- |
| `dashStrike` 突進 | 伏特、蒼瀧、鋼獄 |
| `burst` 周身爆發 | 伏特 |
| `projectile` 彈道（可追蹤／爆散） | 燼火、霜稜、星蝕、鋼獄必殺 |
| `uppercut` 昇龍 | 燼火 |
| `ward` 護盾架勢 | 蒼瀧、鋼獄 |
| `beam` 光束 | 蒼瀧必殺 |
| `boomerang` 迴旋刃 | 疾翎 |
| `divekick` 俯衝踢 | 疾翎 |
| `vortex` 龍捲 | 疾翎必殺 |
| `spikes` 地刺 | 霜稜、熔岳 |
| `fieldFreeze` 全場凍結 | 霜稜必殺 |
| `zone` 場域 | 蝕紫（技能與必殺） |
| `rushCombo` 連斬 | 燼火必殺、蝕紫 |
| `slam` 砸地衝擊波 | 熔岳 |
| `rain` 天降 | 熔岳必殺 |
| `gravity` 引力井 | 星蝕 |
| `supernova` 超新星 | 星蝕必殺 |
| `blink` 瞬移斬 | 夜刃 |
| `decoy` 虛影 | 夜刃 |
| `flurry` 連打 | 伏特必殺、夜刃必殺 |

元件分兩類：有自己生命週期的 **Entity**（飛行物、場域、光束、地刺、衝擊波），
以及「一段時間內操控施放者」的 **Routine**（突進、連斬、瞬移、蓄力）。
角色資料只填 `kind` 與參數，視覺再用自己的顏色與形狀做出辨識度。

## 5. 輸入：一種格式打天下（`input.js`）

鍵盤、觸控、AI、網路對手，最後都收斂成同一個 `InputFrame`：

```js
{ x: -1|0|1, up, down, edges }   // edges 是按鍵「剛按下」的位元遮罩
```

因為只有一種格式，`Fighter` 完全不知道操作者是誰 ——
單機、雙人同機、連線走的是同一條程式路徑，不必維護三套。

`edges` 用位元遮罩是為了連線：一幀的輸入就是四個數字。

## 6. AI（`ai.js`）

AI 不碰戰鬥邏輯，只產生 `InputFrame`，所以它一樣吃冷卻、硬直與格擋規則，不會作弊。
難度只調整兩個數字：反應間隔與積極度。行為是距離導向的 ——
近距離挑普攻或後退、中距離挑合適的技能、對手在出招時會往後格擋、氣滿了會找機會放必殺。
夜刃的虛影對 AI 是真的有效：`battle.apparentTarget()` 會把虛影當成目標回傳。

## 7. 連線（`net.js` / `server/relay.js` / `battle.js`）

* **中繼伺服器**只做一件事：同房號的兩個人互轉封包。它不懂遊戲規則，
  所以遊戲改版完全不用動伺服器。手寫 WebSocket（RFC 6455 必要子集），零相依套件，
  同一支程式順便把遊戲的靜態檔案服務出去。
* **主機權威**：先進房的人是主機，跑完整模擬，每秒 20 次送快照；
  客戶端只送輸入（60Hz、每幀四個數字）與照著快照畫。
* **客戶端不算傷害**：`Battle.authoritative = false` 時 `dealDamage()` 直接回傳 false，
  所以即使客戶端在本地重播招式特效，也不會扣到血。
* **招式重播**：主機把「誰放了什麼招」轉過去，客戶端跑同一支 `runSkill`，
  於是彈道、光束、地刺這些東西兩邊都看得到。
* **索引對齊**：快照裡 0 號永遠是主機、1 號永遠是客戶端，客戶端照樣把自己畫在自己那側。
  （前一版 Godot 專案就是在這裡出過 bug：客戶端的血條顯示的是對手的血量。）
* **心跳**：伺服器每 15 秒 ping，45 秒沒回應就踢掉，
  否則瀏覽器分頁被強制關掉時那個房號會永遠卡在「已經有兩個人」。

## 8. 音效（`audio.js`）

全部即時合成，沒有音檔：打擊是帶通噪音 + 方波、重擊多一層低頻鋸齒、
揮空是掃頻噪音、必殺是三個疊起來的鋸齒和弦。
背景音樂是 16 步的循環（低音線 + 琶音），音量壓得很低當底噪。
瀏覽器規定要有使用者互動才能出聲，所以 AudioContext 延到第一次按鍵／點擊才建立。

## 10. 打包（`tools/build.js`）

瀏覽器用 `file://` 開啟時會擋下 ES module，所以「點兩下就能玩」的版本要把所有模組
塞進同一個 HTML。做法是把每支模組的原始碼存成字串，在瀏覽器裡轉成 `blob:` URL 再互相
import —— **程式碼一個字都不用改**，也就不會有「打包版和開發版行為不同」的問題。
打包器會做相依排序，發現循環 import 會直接報錯（目前的相依圖是無環的）。
